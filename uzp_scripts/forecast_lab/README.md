# forecast_lab — подбор формулы прогноза портфеля

Отдельный инструмент. Дэш `tb_health` он **не меняет**: наоборот, импортирует его
рабочую формулу, чтобы «текущий вариант» в переборе был ровно тем кодом, что
стоит на проме.

## Зачем

Формула дэша задана вручную:

```
прогноз = портфель(закрытый месяц) − ожидаемый отток + сезонный приход + пайплайн
```

и на проме она неточная. Лаборатория берёт исторические факты, гоняет по ним
десятки тысяч вариантов формулы и показывает, какой точнее — с честной проверкой
и с указанием, сколько в таблице лидеров подгонки.

## Постановка

| | |
|---|---|
| Минимизируем | ошибку **выполнения плана по единицам** (ГОСБ×сегмент, ГОСБ) |
| Метрика | получатели (`12400196`); ФОТ считается той же формулой, проверкой |
| Горизонт | **начало месяца, 1–5 число** — наблюдаемого оттока ещё нет |
| Признаки | только история. Колонки, смотрящие вперёд, запрещены и проверяются тестом |

## Про приход и двойной счёт

Прямого измерения органического прихода в витрине нет. `new_fl_cnt` — не он:
столбец заполняется только там, где сотрудник завёл сделку, то есть по смыслу
совпадает с фактом привлечения по пайплайну. Поэтому основной способ поймать
приход здесь другой — **чистая дельта самой численности**, аддитивная
(`fl(M−1) − fl(M−2)`, сглаженная) и мультипликативная (сглаженное отношение, с
усадкой к темпу сегмента). От `new_fl_cnt` они не зависят никак.

Насколько учётные столбцы вообще описывают движение портфеля — не предмет
мнения: лаборатория считает это числом и кладёт в `coverage.csv`. Прирост и убыль
берутся из самой численности (`Σ max(Δfl, 0)` и `Σ max(−Δfl, 0)`), дальше — доля,
которую покрывают `new_fl_cnt`, `fl_outflow_qty` и `fact_outflow`.

Отсюда два запрета в сетке, оба про двойной счёт:

* **чистая дельта против оттока** — прирост уже включает ушедших;
* **приход из истории против пайплайна** — сглаженная дельта, темп прироста и
  среднее `new_fl_cnt` уже содержат привлечение прошлых месяцев, а план
  пайплайна добавляет его ещё раз. Исключение — сезонный приход текущей формулы:
  это возврат ранее ушедших, и сегодняшняя формула дэша обязана остаться
  представимой в переборе (проверяется тестом).

Вариант с двойным счётом опасен не тем, что он неточен, а тем, что может
случайно погасить чужую ошибку, выиграть перебор и развалиться на новых месяцах.
Снять второй запрет и измерить, сколько на нём теряется, можно параметром
`allow_double_count=True`.

## Как запускать

Из `forecast_lab.ipynb`, по ячейкам сверху вниз. Первый прогон на проме:

1. **Самопроверки** — секунды. Не прошли — дальше идти нельзя.
2. **Разведка** — минуты. Пишет `probe.json`: глубина истории, заполненность
   признаков, лаг загрузки закрытого месяца, расхождение уровней витрины.
3. **Выгрузка** — около часа, один раз. Панель (ГОСБ, организация, месяц) режется
   на чанки не больше 1 млн строк и кладётся в кэш на диск.
4. **Перебор** — минуты, гоняется по кэшу сколько угодно раз.

Повторный запуск переиспользует кэш: обрыв на середине выгрузки не означает
«начать сначала». Пересобрать принудительно — `force_fetch=True`.

## Что отправлять наружу

Всё содержимое `output/forecast_lab/`, **кроме**
`pseudonyms_НЕ_ПЕРЕСЫЛАТЬ.csv`. В остальных файлах ИНН и названий нет, ТБ и ГОСБ
идут псевдонимами.

| файл | что внутри |
|---|---|
| `RESULTS.md` | короткая сводка: лидеры, конкуренты, вклад слагаемых, ограничения |
| `leaderboard.csv` | все варианты × грейн × метрики |
| `by_month.csv` | лидеры помесячно (и проверка по ФОТ) |
| `by_unit.csv` | ошибка по каждой единице — где именно прогноз врёт |
| `ablation.csv` | во что обходится отключение каждого слагаемого |
| `honest_selection.csv` | победитель, выбранный по прошлым месяцам |
| `by_orgs.csv` | точность на грейне организаций для лидеров |
| `coverage.csv` | сколько движения портфеля объясняют учётные столбцы |
| `family_best.csv` | лучший результат каждого семейства слагаемых |
| `probe.json` | что нашлось в данных |
| `run_config.json` | с какими параметрами считалось |

## Устройство

```
lab/probe.py     разведка данных
lab/fetch.py     выгрузка чанками + кэш (широкие матрицы «пара × месяц»)
lab/models.py    семейства кандидатов, всё векторизовано
lab/backtest.py  rolling origin, свёртка к единицам, скоринг
lab/report.py    обезличенные результаты
lab/run.py       оркестратор
tests/check_lab.py  самопроверки
```

Ключевое решение по производительности: слагаемые независимы, а свёртка к
единице — сумма, поэтому каждый вариант слагаемого считается по организациям
**один раз**, а комбинируются варианты уже на грейне единиц, где строк семьсот, а
не 5.7 млн.

## Чего лаборатория не сделает

* Не даст выводов о сезонности: 13 месяцев истории для этого мало физически.
* Не оценит вклад дневной витрины на главном горизонте — на 1–5 число её ещё нет.
* Не поменяет `forecast.py`: перенос победившей формулы в дэш — отдельная работа.
* Прогон на синтетике проверяет только механику; выводы о точности верны только
  для прома.
