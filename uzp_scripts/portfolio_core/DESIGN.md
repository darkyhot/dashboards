# portfolio_core — единая подложка портфеля ФЛ

Цель: один раз в месяц разметить, что произошло с каждым получателем ЗП, и хранить
результат сводкой «месяц × id орг × ГОСБ». Любой вопрос про портфель (просадка
сегмента, совместительство, зп / не зп, разовые, дожитие) отвечается запросом к
сводке, без нового чтения ведомостей и без нового проекта.

**Папка автономна:** всё — эталон портфеля, подключение, синтетика, проверки — лежит
здесь. Ни импорта, ни ссылок на другие папки проекта.

---

## 1. Ограничения, из которых исходит схема

| Ограничение | Следствие |
|---|---|
| Ведомости физически не хранить | Всё, где есть человек (`epk_id`), живёт только во временных таблицах одного прогона |
| Хранить можно сводку «месяц × id орг × ГОСБ» в `s_grnplm_ld_salesntwrk_pcap_sn_t_uzp`, имена с префиксом `yva_` | Числа, которые нужны дальше, считаются по людям и сворачиваются до этого уровня до записи |
| Зачисления пересчитываются задним числом (обычно с начала года, бывает глубже) | Каждый прогон пересчитывает всё окно и заменяет сводку целиком; итоги каждого прогона копятся в журнале |
| Ведомости читаются один раз за прогон | Одна временная копия за всё окно, по месяцу на оператор |
| Окно | Скользящие последние 36 месяцев (сейчас с 2023-11 — с этой даты определён отбор relev) |

## 2. Определения

* **Отбор зачислений и портфель** — логика заказчика (раздел 7): ведомости
  `uzp_data_payroll_m` (колонки — как в `mis_data_payroll_m`; имя таблицы —
  параметр тетрадки), перекодировка ГОСБ, relev, портфельные виды по
  `uzp_dim_enrollment_type.is_portfolio_enrollment`, порог 2500 по тройке, вид 2,
  организации без порога. ТИК/ЦИК (`yva_tik_cik`) исключены целиком.
* **Получатель** — тройка (`epk_id`, id орг, `sys_gosb_id`).
* **Зп-коды** — портфельные виды (`uzp_dim_enrollment_type.is_portfolio_enrollment`),
  остальные — не зп.
* **Состояние тройки в месяце** (по relev-строкам с суммой > 0):
  `P` — в портфеле; `Z` — есть зп-коды, но тройка не в портфеле (ниже порога);
  `N` — только не зп коды;
  тройки нет — зачислений нет.
* **ФЛ в пересчёте** — человек с k тройками в портфеле даёт 1/k каждой. Сумма по
  банку = число людей. Совместительство среза = получатели − ФЛ.
* **Сегмент** — исторический, на каждый месяц: `uzp_data_payroll_segment_month_2021`
  (перекодировка ГОСБ и сегмента — как у заказчика). Если пары нет в истории —
  текущий сегмент ЕПК, источник помечается.
* **Холдинг** — текущий срез ЕПК (`holding_name`); в сводке не хранится,
  подтягивается по id орг в запросе.
* **Разовый** — тройка, у которой во всём окне ровно один месяц с зачислениями (не в
  первом месяце окна). Подтверждается через 2 месяца, до этого — предварительно.
* **Пропуск** — нет в портфеле 1 месяц, в следующем снова есть.

## 3. Метки движений

Месяц M сравнивается с базой B. Три базы: `m_` — B = M−1, `q_` — B = M−3,
`y_` — B = M−12.

**Пришёл** (в портфеле в M, нет в B) — первое подошедшее:

| Метка | Условие в B |
|---|---|
| `in_from_nonzp` | тройка в состоянии `N` |
| `in_from_zp_out` | тройка в состоянии `Z` |
| `in_from_other_org` | у человека была другая тройка в портфеле |
| `in_returned` | у человека не было портфеля в B, но был раньше в окне |
| `in_new_bank` | портфеля в окне раньше не было |

`in_from_other_org` = `in_oth_same_org` (та же организация, другой ГОСБ) +
`in_oth_same_hold` (тот же холдинг) + `in_oth_other`.

**Ушёл** (в портфеле в B, нет в M) — первое подошедшее:

| Метка | Условие в M |
|---|---|
| `out_to_nonzp` | тройка в состоянии `N` |
| `out_zp_out` | тройка в состоянии `Z` |
| `out_to_other_org` | у человека есть другая тройка в портфеле |
| `out_left_bank` | у человека нет ни одной тройки в портфеле |

`out_to_other_org` = `out_oth_same_org` + `out_oth_same_hold` + `out_oth_other`.

`out_left_bank` = `lb_seasonal` (год назад тот же провал: тройка была в портфеле в
M−13, не было в M−12, снова была в M−11; идёт первой — сезонно может пропадать и вся
организация) + `lb_org_stopped` (организация в M не платит в портфель ни в одном
ГОСБ) + `lb_one_time` (тройка разовая) + `lb_unknown` (**причина неизвестна**).
Для базы `y_` сезонный уход всегда 0: тройка была в портфеле ровно год назад, значит
провала в этом месяце год назад не было.

**Люди:** `fl_in` — пришедшие, у которых в B не было портфеля нигде (вес 1/k в M);
`fl_out` — ушедшие, у которых в M портфеля нет нигде (вес 1/k в B);
`fl_conc` = Δ`pf_fl` − `fl_in` + `fl_out` — изменение от совместительства.
По банку `fl_conc` = 0.

**Тождества** (самопроверка каждого прогона, на каждой строке):
`pf_recip − base_pf = Σ in − Σ out`; части равны целому.

**Кварталы и годы.** Портфель периода — средний по месяцам. Изменение среднего —
среднее изменений: квартал к кварталу = среднее `q_` за 3 месяца, период к тому же
периоду год назад = среднее `y_`. Разложение по меткам переносится без пересчёта.

## 4. Таблицы в `s_grnplm_ld_salesntwrk_pcap_sn_t_uzp`

### `yva_ptf_month_org` — главная сводка

Строка = (месяц, id орг, ГОСБ), если у пары были тройки в M или портфель в одной из
баз. Пересоздаётся каждым прогоном (`_new` + подмена). На Greenplum — постолбцовое
хранение со сжатием, распределение по (id орг, ГОСБ).

| Группа | Столбцы |
|---|---|
| ключ и разрезы | `report_dt`, `org_id` (bigint), `sys_gosb_id`, `sys_tb_id`, `seg`, `seg_src` |
| остатки | `pf_recip`, `pf_fl`, `pf_amt`, `fot_amt`, `zp_out_recip`, `nonzp_recip`, `any_recip` |
| совместительство | `multi_recip`, `multi_same_org`, `multi_same_hold`, `multi_other` |
| зп / не зп | `flip_to_nonzp`, `flip_to_zp`, `flapping_recip` |
| разовые | `one_time_recip`, `one_time_pf`, `one_time_person` |
| стаж | `ten_lt3`, `ten_3_12`, `ten_12_24`, `ten_24p` |
| дожитие пришедших | `surv3`, `surv6`, `surv12`, `surv12_bank` |
| движения × {m, q, y} | `base_pf`, `base_seg`, 5 `in_*`, 3 `in_oth_*`, 4 `out_*`, 3 `out_oth_*`, 4 `lb_*`, `fl_in`, `fl_out`, `fl_conc` |
| только m | `m_out_temp` — ушедшие, вернувшиеся в M+1 |

Для месяцев, где база выходит за окно, столбцы этой базы пусты (NULL).

### `yva_ptf_runs` — журнал прогонов (копится)

Строка = месяц окна в прогоне: `run_id`, `run_ts`, `report_dt`, `window_from`,
`window_to`, `pf_recip`, `pf_fl`, `fot_amt`, `any_recip`, `raw_rows`,
`seg_hist_share`, `one_time_prelim`, `checks_ok`, `duration_min`.

## 5. Прогон

1. Справочники во временные таблицы: ТИК/ЦИК, организации без порога, ЕПК (свёрнут
   до id орг), исторический сегмент.
2. Копия ведомостей за окно — оператор на месяц, узкие колонки, признаки сразу.
3. Тройки по месяцам: состояние, суммы, ФОТ.
4. Люди по месяцам; истории троек и людей.
5. Метки трёх баз, остатки, совместительство, разовые, стаж, дожитие.
6. Сборка `yva_ptf_month_org_new`, самопроверки, подмена, запись журнала.

## 6. Этапы

1. **Подложка** — этот раздел. Приёмка: синтетика сходится с независимым эталоном
   на pandas; на проме портфель по месяцам сверяется с payroll_bank_yoy (он читает
   `mis_data_payroll_m`, поэтому расхождение между витринами печатается, а не
   считается ошибкой).
2. **Сторож** уровней 1–2 и ежемесячный HTML.
3. **Поиск новых закономерностей**, предвестники оттока, карта перетоков.

## 7. Эталон отбора заказчика

* Перекодировка ГОСБ: ТБ 38 → 9038; ГОСБ 1009 → 8557; ГОСБ 0 в ТБ 40 → 9040; сырой
  сегмент КСБ в ГОСБ 8591 → 8646.
* «Не определено» в номере организации → '0'.
* relev: вид «Основные» и доля рынка не «ИП 1 чел.» (с января 2024; ноябрь–декабрь
  2023 — без этих условий); организация не Сбер (7707083893) и не заглушка
  ('Не определено', '0', '-1').
* Строка в портфеле: relev, сумма > 0 и одно из трёх: портфельный вид и сумма
  портфельных видов тройки за месяц > 2500; вид 2; портфельный вид и организация без
  порога (`uzp_dim_education_organization` ∪ ЕПК `reference_holding_name` =
  'МИНОБОРОНЫ').
* ФОТ — то же с `is_fot_enrollment` и суммой ФОТ-видов тройки.
* Номер организации в ведомостях — текст; в число только под маской `^[0-9]{1,12}$`.
