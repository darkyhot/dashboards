# portfolio_core — подложка портфеля ФЛ (определения, этап 1.5)

Раз в месяц размечаем, что произошло с каждым получателем ЗП, и храним результат
сводкой «месяц × id орг × ГОСБ». Любой вопрос про портфель отвечается запросом к
сводке, без нового чтения ведомостей. План системы — `PLAN.md`.

**Папка автономна:** всё — эталон портфеля, подключение, синтетика, проверки — лежит
здесь. Ни импорта, ни ссылок на другие папки проекта.

---

## 1. Ограничения

| Ограничение | Следствие |
|---|---|
| Ведомости физически не хранить | Всё, где есть человек (`epk_id`), живёт только во временных таблицах прогона |
| Хранить можно агрегаты «месяц × id орг × ГОСБ» и крупнее, в `s_grnplm_ld_salesntwrk_pcap_sn_t_uzp`, имена `yva_` | Числа по людям сворачиваются до записи |
| Зачисления пересчитываются задним числом | Каждый прогон пересчитывает всё окно; поколения и журнал копятся |
| Ведомости читаются один раз за прогон | Каждый месяц сразу сворачивается до тройки (`t_tr`), оператор на месяц |
| Окно | Последние 36 месяцев, но не раньше 2023-11 (раньше отбор relev не определён) |

## 2. Определения

* **Отбор и портфель** — логика заказчика (раздел 8): ведомости `mis_data_payroll_m`
  (имя — параметр), перекодировка ГОСБ, relev, портфельные виды, порог 2500 по тройке,
  вид 2, организации без порога. ТИК/ЦИК (`yva_tik_cik`) исключены целиком.
* **Получатель** — тройка (`epk_id`, id орг, `sys_gosb_id`).
* **Зп-коды** — портфельные виды (`is_portfolio_enrollment`), остальные — не зп.
* **Состояние тройки в месяце** (по relev-строкам с суммой > 0): `P` — в портфеле;
  `Z` — есть зп-коды, но не в портфеле (ниже порога); `N` — только не зп коды.
* **ФЛ в пересчёте** — человек с k тройками в портфеле даёт 1/k каждой; по банку = число
  людей. Точное число разных людей по срезам — в журнале (раздел 5).
* **Сравнения** — с M−1 (`m_`) и с M−12 (`y_`). Квартал к кварталу раскладывается суммой
  помесячных `m_` (валовые потоки за квартал), отдельной базы нет.
* **Ноябрь–декабрь 2023** отбирались по другим правилам relev. Эти месяцы — только
  память; сравнения с базой в них пусты.
* **Память — ровно 12 месяцев.** «Вернулся», разовые, стаж, сезон смотрят на 12 месяцев
  назад; где истории меньше — значение пусто (NULL), а не «новый». Поэтому метки не
  меняются, когда окно сдвигается (проверка `check_window_shift`).
* **Разовый (причинно)** — в месяце t есть зачисления, а в t−12…t−1 и в t+1, t+2 нет.
  Последние 2 месяца окна — «предварительно» (`prelim`): будущего ещё нет.
* **Стаж в портфеле**: `lt3` — не было в портфеле в t−12…t−3; `12p` — был ровно год
  назад; иначе `3_12`.
* **Сезонный уход в M** — год назад тот же провал: в портфеле в M−13, нет в M−12,
  вернулся в течение 3 месяцев (M−11…M−9).
* **Сегмент — два поля** (словарь заказчика, `uzp_data_payroll_segment_month_2021`):
  * `seg_rep` — сегмент в месяце строки; пары нет в истории — текущий ЕПК (`seg_src`);
  * `seg_cur` — текущий: последний **полный** месяц истории (доля портфеля с историей
    ≥ 90% медианы окна) по паре, иначе по организации, иначе ЕПК. Месяц — в журнале;
  * `{m,y}_base_seg` — `seg_rep` в месяце базы (перевод между сегментами).
* **Холдинг** — текущий срез ЕПК (`holding_name`), в сводке не хранится.

## 3. Метки движений

**Пришёл** (в портфеле в M, нет в B) — первое подошедшее: в B тройка `N` →
`in_from_nonzp`; `Z` → `in_from_zp_out`; у человека в B другая тройка в портфеле →
`in_oth_same_org` / `in_oth_same_hold` / `in_oth_other`; портфель был в B−12…B−1 →
`in_returned`; иначе `in_new_bank`. `in_from_outside` = новый + вернулся — заполнен
всегда, когда есть база.

**Ушёл** (в портфеле в B, нет в M) — первое подошедшее: в M `N` → `out_to_nonzp`;
`Z` → `out_zp_out`; у человека в M другая тройка → `out_oth_*`; иначе ушёл из банка,
причина: `lb_seasonal` → `lb_org_stopped` (организация в M не платит в портфель ни в
одном ГОСБ) → `lb_one_time` (тройка разовая в B) → `lb_unknown`. Для `y_` сезонного
ухода не бывает (тройка была в портфеле ровно год назад), столбца нет.

**Люди:** `fl_in` / `fl_out` — пришли / ушли люди, у которых портфеля нет нигде в B / M;
`fl_conc` = Δ`pf_fl` − `fl_in` + `fl_out` — изменение от совместительства (по банку 0).

**Тождество** (каждая строка, каждый прогон): `pf_recip − base_pf = Σ in − Σ out`,
части = целому.

### Пустые значения (NULL)
| Столбцы | Пусто, если |
|---|---|
| все столбцы базы b | месяц базы раньше 2024-01 |
| `in_new_bank`, `in_returned`, `lb_*` | ещё и до базы меньше 12 месяцев истории |
| `ten_*`, `one_time_*` | до месяца меньше 12 месяцев истории |
| `flapping_recip` | меньше 12 месяцев сравнимых состояний |
| `m_out_temp` | нет базы или следующего месяца |
| `m_out_ten_*` | нет базы или 12 месяцев истории до неё |

## 4. Сводка `yva_ptf_month_org` (80 столбцов)

Строка = (месяц, id орг, ГОСБ), если у пары были тройки в M или портфель в одной из баз.

| Группа | Столбцы |
|---|---|
| ключ и разрезы | `report_dt`, `org_id`, `sys_gosb_id`, `sys_tb_id`, `seg_rep`, `seg_cur`, `seg_src` |
| остатки | `pf_recip`, `pf_fl`, `pf_amt`, `fot_amt`, `zp_out_recip`, `nonzp_recip`, `any_recip`, `raw_rows` (строк ведомостей) |
| одна выплата | `single_pay_recip` — в портфеле с одной выплатой за месяц (носитель календарного сдвига) |
| совместительство | `multi_recip`, `multi_same_org`, `multi_same_hold`, `multi_other` |
| коды | `flapping_recip` — ≥ 3 смен зп ↔ не зп за 12 мес. |
| разовые | `one_time_pf`, `one_time_person` (человек разовый во всём банке), `prelim` |
| стаж | `ten_lt3`, `ten_3_12`, `ten_12p` |
| движения × {m, y} | `base_pf`, `base_seg`, `in_from_outside`, `in_new_bank`, `in_returned`, `in_from_other_org`, `in_from_nonzp`, `in_from_zp_out`, 3 `in_oth_*`, `out_left_bank`, `out_to_other_org`, `out_to_nonzp`, `out_zp_out`, 3 `out_oth_*`, `lb_*`, `fl_in`, `fl_out`, `fl_conc` |
| только m | `m_out_temp` (вернулись в M+1), `m_out_ten_lt3/3_12/12p` (ушедшие по стажу — вместе со стажем дают таблицу дожития на любом срезе) |

## 6. Прогон

1. Справочники во временные таблицы; окно; месяц 2024-01 — первый для сравнений.
2. Ведомости → тройки, оператор на месяц (единственное чтение). Пустой месяц валит проверки.
3. Маски истории тройки и человека (`bit_or` по месяцам) вместо самосоединений.
4. Метки двух баз построчно по людям → свёртка; остатки; ключи; сегменты.
5. Сводка и потоки в `_new`; самопроверки; подмена одной транзакцией; поколение; журнал;
   предупреждение о недогрузе ТБ в последнем месяце.

## 7. Проверки на синтетике (открытый контур)

* Сводка, потоки и точное число людей совпадают с независимым эталоном
  (`reference.py`, множества вместо масок) по каждой ячейке.
* ~30 заложенных событий: сезоны 1 и 3 месяца ловятся, 4 месяца — нет; реорганизация на
  60 человек — одна пара; неполный последний месяц истории сегментов не берётся
  текущим; до 2024-01 сравнений нет и т.д.
* Сдвиг окна: прогоны на M и M+1 совпадают по общим месяцам во всех непустых ячейках.
* 1 и 4 куска по людям дают одинаковый результат.

## 8. Эталон отбора заказчика

* Перекодировка ГОСБ: ТБ 38 → 9038; ГОСБ 1009 → 8557; ГОСБ 0 в ТБ 40 → 9040; сырой
  сегмент КСБ в ГОСБ 8591 → 8646.
* «Не определено» в номере организации → '0'.
* relev: вид «Основные» и доля рынка не «ИП 1 чел.» (с января 2024; ноябрь–декабрь
  2023 — без этих условий); организация не Сбер (7707083893) и не заглушка
  ('Не определено', '0', '-1').
* Строка в портфеле: relev, сумма > 0 и одно из трёх: портфельный вид и сумма
  портфельных видов тройки за месяц > 2500; вид 2; портфельный вид и организация без
  порога (`uzp_dim_education_organization` ∪ ЕПК `reference_holding_name` =
  'МИНОБОРОНЫ').
* ФОТ — то же с `is_fot_enrollment` и суммой ФОТ-видов тройки.
* Номер организации в ведомостях — текст; в число только под маской `^[0-9]{1,12}$`.
