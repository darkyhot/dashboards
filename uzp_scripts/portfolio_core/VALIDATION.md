# Сторож: статус проверки

Протокол 2, 2026-11-02. Полная приёмка **не пройдена**: требование полноты на трёх
шумах остаётся невыполненным. Числа ниже относятся к синтетике.

## Проверяемая версия

Включены исправления локализации и повторных карточек, общего календарного сдвига,
направления отклонения, физической допустимости закладок и соперника. Все уровни
считаются по исходным наблюдениям. Повторные карточки снимаются только при доказанном
вложении территории и совпадении потока и направления. Отдельно исправлена подпись
остановки организации: уменьшение ухода не считается остановкой.

29 регрессионных тестов и самопроверки проекта проходят. Ячейки Jupyter сохраняют
HTML и JSON: проверки, все карточки, пропущенные события с параметрами модели,
артефакты, полноту разметки причин ухода и хеши файлов. Один запуск собирает весь
материал для разбора.

## Проверка на полном размере

Панель: 4 137 организаций, 506 атомов, 33 месяца. Повышенный шум (множитель 1,6),
меняющиеся доли причин ухода, 40% организаций распределяются между двумя ГОСБ.
75 закладок дают 87 целей: у реорганизации проверяются обе стороны.
Seeds панели и плана — 277 и 1277. Эти данные использовались для сравнения вариантов;
это воспроизводимая проверка, а не независимый экзамен после настройки.

| Проверка | Требование | Результат |
|---|---:|---:|
| Крупные события: от четырёх шумов и 2 тыс. человек | ≥ 90% | 10/11, 90,9% |
| Три шума, от 300 человек | ≥ 50% | 0/5 |
| Ложные карточки в месяц на чистом фоне | ≤ 5 | 3,7 |
| Эхо провала | ≤ 5% | 0% |
| Лишние карточки от календаря / недогруза / смены ГОСБ | 0 / 0 / 0 | 0 / 0 / 0 |
| Ошибки закладки и отрицательные остатки | 0 | 0 |

Выборка из пяти событий в три шума мала; её результат нельзя считать точной оценкой
полноты на реальных данных. Однако она не даёт основания объявлять приёмку успешной.
Порог 50% сохранён. Статический отбор множества рядов и минимум в 100 человек после
вычета шума затрудняют поиск таких событий. Это нерешённое ограничение текущей модели.

Проверялась дополнительная оценка по составу необъяснённых уходов и изменение
калибровки. На тех же событиях итоговый вариант дал 9/11 крупных событий и 7,2 ложной
карточки в месяц. Он отвергнут и не входит в обновление. Сравнение на небольших
панелях этого ухудшения не выявило.

## Как воспроизвести

Из папки `portfolio_core`:

```bash
python3 -m unittest discover -s tests -v
python3 -c 'from ptf import selfcheck; selfcheck.run_all()'
```

Полноразмерная проверка, обычный Python-код (также работает в ячейке Jupyter):

```python
from ptf import acceptance, bench

panel = bench.simulate(seed=277, n_orgs=4137, gosb_per_tb=6, noise_scale=1.6)
panel = bench.vary_departure_reasons(panel, seed=280)
panel = bench.spread_organizations(panel, seed=278)
report = acceptance.run(panel, "output/watch_local_validation", compare=True,
                        known_clean=True, seed=1277, per_cell=3, per_size=1,
                        max_details=6)
```

Расширенный прогон на пяти панелях по 1 200 организаций:

```bash
python3 -m ptf.validation --output output/watch_validation
```

Он проверяет обычный фон, несколько ГОСБ, повышенный шум, события в прошлой истории
и меняющийся состав причин ухода. Код возврата 1 означает невыполненный критерий.
Таблица выше относится к отдельной полноразмерной проверке.

## Границы проверки

Синтетика не доказывает качество на реальном поколении. На проме число карточек
исходного фона включает настоящие события и не является числом ложных тревог.
Статистическое объяснение перехода между ГОСБ не доказывает административную
перекодировку. Известные случаи аналитика остаются отдельной проверкой.

Последний месяц не имеет подтверждённого возврата следующего месяца: календарная
поправка по возвратам в нём не применяется. Остановка организации проверяется в
последнем месяце. Изменения годовых объединений людей этой приёмкой не проверяются.
