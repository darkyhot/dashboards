# portfolio_core — правила работы агента

## Цель (PLAN.md)
Автоматический аналитик зарплатного портфеля: сам находит существенные изменения,
показывает масштаб и источники, отличает внутренние перемещения от потери людей,
объясняет подтверждённую часть механизмами, неизвестный остаток оставляет видимым;
затем предупреждения и прогноз. Один запуск → связный бизнес-отчёт + короткие страницы для фото.
Сторож — указатель «куда смотреть», не цель сам по себе.

## Источники истины — читать до любого предложения
- `PLAN.md` — шаги, текущий статус, критерии готовности. **Решения пользователя вносить сюда сразу.**
- `DESIGN.md` — подложка: таблицы, метки движений, правила NULL.
- `methodology.md` — расчёты сторожа и бизнес-разбора. `VALIDATION.md` — журнал проверок.
- `known_cases.csv` — реальные кейсы аналитика = экзамен, не настройка. Номера организаций не выводить.
- `HANDOFF.md` — исторический срез передачи; актуальны PLAN и этот файл.
- Раздел PLAN «Требования исходного плана, выпавшие при переписывании 05.11» — обязательный
  чек-лист шагов 2–6. Старые версии плана — `git show 2dc7a4e:uzp_scripts/portfolio_core/PLAN.md`;
  при сомнении сверять с ними, а не с памятью.

## Рамки этапа (пользователь, 10.11.2026)
1) искать отклонения сам; 2) объяснять и показывать **реальное изменение**: отчётное =
нереальные составляющие (перенос выплат, временный отток, коды, переводы…) + реальное;
3) прогнозировать портфель. Плюс система сама вводит новые метрики (PLAN 3.4; пример —
уход пришедших за последние 3 мес.). Фото — только настройка; итог — артефакты для защиты
(каждое число воспроизводимо, SQL, методика). Предупреждения (шаг 4), задачи, расписание, слияние с
соседними разборами — вне этапа. Порядок 2 → 3 → 5 → 6.

## Правила пользователя
- Код запускается на проме (DataLab, Greenplum 9.4, без интернета) только ячейками
  `portfolio_core.ipynb`; навык `datalab-code-rules`. Вторую тетрадку и `%run` не предлагать.
- Результаты приходят только фотографиями. Файлы выгрузить не просить.
- **Параметры ячеек (разделы, страницы, месяцы) правлю сам**; пользователь подменяет тетрадку
  и запускает. В ответе: какую ячейку запустить и какие фото нужны. Сборку (95 мин) и стенд
  (~1 ч) — только с конкретной доказанной целью.
- Номера организаций маскировать везде. Пустое значение ≠ 0. Приёмку не ослаблять без решения
  пользователя. Постоянно хранить только агрегаты `yva_`.

## Бизнес-принципы аналитика
- Сезон известен (январь, декабрьская зарплата и т. п.). Интересно **отличие от обычного**, и
  каждое отличие объясняется проверяемыми механизмами. «Год к году» — одно из сравнений: система
  сама перебирает окна (1/3/6/12 мес.) и базы (без базы, год и два года назад, среднее лет), PLAN 2.2.
- Термины: «временный отток» (ушли и вернулись в следующем месяце), не «пропуск».
- «Обычные колебания» — не объяснение.
