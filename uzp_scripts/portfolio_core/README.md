# portfolio_core — единая подложка портфеля ФЛ

Раз в месяц читает ведомости за последние 36 месяцев, размечает, что случилось с
каждым получателем ЗП, и хранит результат сводкой «месяц × id орг × ГОСБ». Любой
вопрос про портфель отвечается запросом к сводке — без нового чтения ведомостей.

Что и как считается — [DESIGN.md](DESIGN.md).

## Что появляется в БД

В `s_grnplm_ld_salesntwrk_pcap_sn_t_uzp`:

| Таблица | Что это |
|---|---|
| `yva_ptf_month_org` | сводка: 104 столбца, строка = месяц × id орг × ГОСБ. Пересоздаётся каждым прогоном |
| `yva_ptf_runs` | журнал: итоги каждого прогона по месяцам. Копится — по нему виден пересчёт прошлого |

Людей в постоянных таблицах нет: всё, где есть `epk_id`, живёт только во временных
таблицах прогона. Сводка подменяется, **только если сошлись все самопроверки**;
иначе старая остаётся, а новая лежит в `yva_ptf_month_org_new` для разбора.

## Как запускать

Тетрадка `portfolio_core.ipynb`, по ячейкам сверху вниз:

1. Самопроверки — секунды. Не прошли — дальше нельзя.
2. Параметры и запуск. `REPORT_MONTH` задаётся явно — последний закрытый месяц.
3. Итоги: проверки, портфель по месяцам, пересчёт прошлого, самые долгие шаги.
4. Примеры запросов к сводке.

**Первый прогон на проме** — `N_MONTHS = 13`: по времени одного месяца видно,
сколько займёт полный (36). Если оператор упал по таймауту на шагах «Метки
движений» или «Остатки» — `EPK_CHUNKS = 4`: тяжёлые запросы пойдут кусками по
людям, результат тот же (проверено на синтетике).

## Приёмка на проме

Портфель по месяцам (`res["totals"]`) сверяется с payroll_bank_yoy. Полного
совпадения ждать не нужно: здесь ведомости — `uzp_data_payroll_m`, там —
`mis_data_payroll_m`. Существенная разница — повод проверить витрины, а не код.

В журнале смотреть `seg_hist_share`: какая доля портфеля нашла исторический
сегмент. Низкая доля — ключи истории (дата, номер организации, ГОСБ) не сходятся с
ведомостями, и сегмент берётся из ЕПК.

## Открытый контур

```
docker compose up -d uzp_pg          # из корня проекта
python -m ptf.synth                  # синтетика в схеме synth_ptf
```

Потом прогон в тетрадке с `SCHEMA = SCHEMA_T = "synth_ptf"`, `REPORT_MONTH = "2026-10"`
и последняя ячейка: сводка сверяется с независимым эталоном на Python
(`ptf/reference.py`) по каждой ячейке и с заложенными событиями (сезонники,
организация перестала платить, смена сегмента, разовые, «мигающие» и т.д.).

## Устройство

```
ptf/sql.py        весь SQL
ptf/build.py      прогон: справочники → тройки → люди → метки → остатки → сводка → проверки
ptf/segments.py   сведение сегментов (история и ЕПК)
ptf/selfcheck.py  самопроверки и сверка с синтетикой
ptf/reference.py  независимый эталон (только синтетика)
ptf/synth.py      синтетика
```

Папка автономна: ничего не импортирует из проекта, переносится как есть.
