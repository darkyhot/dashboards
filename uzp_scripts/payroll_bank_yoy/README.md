# payroll_bank_yoy — получатели ЗП по всему Сберу год к году

Отвечает на вопрос: **почему годовая динамика получателей в августе хуже, чем в июле**
(и в июле хуже, чем в июне) — по всему банку и по каждому сегменту. Проверяет три
гипотезы числами: растворились пришедшие в июне–июле; схлопнулось совместительство;
сезонность. Отдельно — где численность реально сократилась (список организаций).

Разбор идёт **до физлица**: списки получателей двух месяцев сравниваются поимённо.

## Главная идея

```
ΔYoY(авг) − ΔYoY(июл) = переход июль→август 2026 − тот же переход 2025
```

Ухудшение годовой динамики в августе по построению равно тому, насколько месячный
переход этого года хуже прошлогоднего. Оба перехода раскладываются одной лестницей
(перестали получать ЗП в Сбере / начали / совместительство), и видно, какое слагаемое
дало разницу. Это работает и для «+, +, −», и для «+, +, + но август меньше июля».

## Постановка

| Вопрос | Решение |
|---|---|
| Получатель | Тройка (ФЛ, организация, ГОСБ) — `(epk_id, inn, sys_gosb_id)`. Засчитывается, если зарплатные зачисления ФЛ в организацию за месяц > 2 500 ₽ по 18 кодам. Совместитель и организация через два ГОСБ — несколько получателей |
| Сегмент | Текущий срез `uzp_data_epk_consolidation`, один на оба года. 6 коротких сегментов + «Не в справочнике» |
| Перестал получать | У ФЛ нет ни одной тройки-получателя где бы то ни было в банке. Сменил организацию или ГОСБ — продолжает получать |
| Реальное сокращение организации | ФЛ перестали получать ЗП в Сбере. Уход в другую организацию — **переток**, отдельная колонка. Реорганизация исключается. В списке только организации, где численность действительно упала |
| Источники | Только `uzp_data_payroll_m`, `uzp_data_epk_consolidation`, `uzp_dim_gosb` |
| LLM | Нет: выводы собираются по правилам из чисел |

Подробно, с формулами и ловушками, — [METHODOLOGY.md](METHODOLOGY.md).

## Что в отчёте

1. **Итог** — год к году за июнь, июль, август; что дало ухудшение (по правилам).
1a. **Потеря или перенос** — вернулся ли минус отчётного месяца в следующем: мост
   m−1 → m → m+1, временные и постоянные уходы, организации, пропустившие месяц
   (с разрезами по сегментам, холдингам, отраслям), двойная выплата у вернувшихся.
2. **Ряд и сезон** — два года по календарному месяцу, изменение год к году, тепловая
   карта «сегмент × месяц», сезонный профиль, обрывы, полнота загрузки.
3. **Разложение год к году** — одно разложение, причины, тепловая карта
   «сегмент × слагаемое».
4. **Почему месяц хуже предыдущего** — разница разниц по слагаемым, стаж
   переставших (пришли в июле / в июне / раньше), вернувшиеся в сентябре, по сегментам;
   переставшие делятся на **отток B2C** (из организации ушло 1–2 ФЛ) и **B2B** (3+).
5. **Растворились ли пришедшие** — доживаемость когорт этого года против прошлого,
   лишняя убыль; где вымываются — по сегментам, холдингам, отраслям, и почему не дожили.
6. **Совместительство** — «лишние» получатели по организациям и по ГОСБ.
7. **Сезонность** — повтор год к году, возврат, зарплатные коды.
7a. **Аванс и зарплата** — у получавших оба вида выплат: не пропал ли один из них
   (сравнение с тем же переходом год назад, по сегментам).
8. **Перетоки между сегментами** — sankey и матрица «откуда × куда».
9. **Территория** — тепловая карта «ТБ × сегмент».
10. **Порог** — картина при 0 … 10 000 ₽.
11. **Организации с реальным сокращением** — разрезы по сегментам, холдингам,
    отраслям (по всем отобранным), список с фильтрами и поиском, сводка по классам,
    исключённые реорганизации.
12. **Проверки** — все тождества и ограничения.

Отдельная **вкладка выделенного холдинга** (`FOCUS_HOLDING`, по умолчанию
«МИНОБОРОНЫ»): итог год к году, ряд, разложение (перестали / начали / переток вне
холдинга / внутри холдинга), почему месяц хуже, отток B2C/B2B, все организации
холдинга, пропуск месяца, пришедшие, аванс и зарплата.

Переключатель месяца (июнь / июль / август) над отчётом меняет все помесячные блоки
сразу. У каждого блока — SQL, которым посчитаны его числа, с параметрами: копируется и
выполняется как есть.

## Запуск

```
payroll_bank_yoy.ipynb   # порядок ячеек обязателен
```

1. описание; 2. установка пакетов (если нужно); 3. самопроверки без БД;
4. **параметры и запуск**; 5. главные цифры; 6. сверка с синтетикой (только открытый
контур); 7. что отправлять.

Отчётный месяц задаётся **явно** (`REPORT_MONTH`). Прогон останавливается, если в
витрине нет нужного месяца; если не загружен месяц после отчётного, отчёт строится,
но проверки возврата в нём нет.

Ведомости читаются **один раз**: узкая копия витрины `t_raw` за все нужные месяцы (ряд,
рабочий набор, месяц после отчётного — около 27 партиций), оператор на месяц. Всё
остальное считается из этой временной таблицы. Время копирования каждого месяца
печатается — первый прогон на проме лучше сделать с `HISTORY_MONTHS = 13`.

Названия организаций и холдингов показываются, **кроме содержащих ФИО** (ИП, КФХ,
адвокаты, нотариусы; признаки — в `names.py`): вместо такого названия — id орг
(номер цифрами), у холдинга — «название скрыто (ФИО)». В обезличенном документе —
токены. Трёхбуквенного слова-идентификатора организации нет нигде в папке (правило 14).

## Автономность

Папка **ничего не импортирует из проекта**: свои подключение к БД, прогресс,
словарь сегментов, графики. Переносится целиком; `.env` ищется в папке и выше
(`BANK_YOY_DB_URL` или `UZP_DB_URL`). Самопроверка `check_self_contained` падает,
если появится импорт вне stdlib, pandas, numpy, sqlalchemy и самого пакета.

## Отладка снаружи

```bash
docker compose up -d                       # Postgres из корня проекта (порт 55433)
cd uzp_scripts/payroll_bank_yoy
python3 -m bank_yoy.synth                  # схема synth_bank_yoy, ~25 с
```

Затем тетрадка с `SCHEMA = "synth_bank_yoy"`. В синтетику заложены события, по одному
на каждую ветку разбора:
- приток новичков в июне–июле 2026, большая часть которых уходит в августе;
- сезонные ямы у одних и тех же людей в оба года;
- уход совместителей РГС со второй работы в августе;
- сведение ГОСБ у части КСБ;
- реорганизации;
- организации с реальным сокращением, «5 ушли — 5 пришли» и с перетоком;
- перенос выплаты: организации не платят в августе и платят вдвойне в сентябре;
- пропажа аванса: организации в августе платят только зарплату;
- холдинг «МИНОБОРОНЫ»: часть людей уходит из Сбера в августе;
- ИП и холдинг с ФИО в названии — в отчёт не должны попасть.

`selfcheck.check_against_synth(res)` требует найти каждое событие.
