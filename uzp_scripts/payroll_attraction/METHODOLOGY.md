# Методика

## 1. Ячейки «ГОСБ × организация»

**Численность ячейки.** Копия `mis_data_payroll_m` за три августа (`t_pay`) — оператор на месяц, только нужные колонки. Перекодировки заказчика:
- ГОСБ: ТБ 38 → 9038; ГОСБ 1009 → 8557; ГОСБ 0 в ТБ 40 → 9040; КСБ в ГОСБ 8591 → 8646;
- организация: «Не определено» → `0`;
- сегмент.

**Признак `relev`** — дословно. Сумма портфельных зачислений `sum_pf` считается по (месяц, ФЛ, ГОСБ, организация). ФЛ входит в портфель, если выполнено одно из трёх:
- `sum_pf > 2500`;
- вид зачисления 2;
- организация без порога (образовательная или холдинг МИНОБОРОНЫ).

ФЛ в ячейке считаются двухступенчато, без `count(DISTINCT)`. Номер организации, не прошедший маску цифр, — общая ячейка −1.

**Классы.** Две пары лет: авг-25→авг-26 и, для сравнения, авг-24→авг-25.
- Рост — +1 и больше. Новая ячейка (0 → n) — тоже рост.
- Снижение — −1 и больше. Закрывшаяся ячейка — тоже снижение.
- Без изменений — 0. Внутри может быть обмен людьми.

**Проверка.** Сумма изменений всех ячеек равна изменению портфеля.

## 2. НФЛ и каналы

**НФЛ.** Архив (`report_dt <= NFL_SPLIT`) и текущая витрина (`> NFL_SPLIT`), фильтр `is_nfl and not is_overflow_fl`, уникальные строки (месяц, ТБ, ГОСБ, организация, ФЛ, первая ЗП). ГОСБ перекодируется так же, как в ведомостях. НФЛ без ЕПК ФЛ в атрибуцию не идут — их число в разделе проверок.

**Действия** ограничены ФЛ из НФЛ: клики и операции ВСП не тянутся целиком.
- **ВСП:** фильтры заказчика, дата — `src_report_dt`. Сжато до «ФЛ × месяц → самая ранняя дата». Этого достаточно: раннее действие месяца не хуже позднего, а конец окна зависит только от месяца. Это и есть DISTINCT ON заказчика.
- **Digital:** клики СБОЛ, `data_timestamp::date`, так же сжато.
- **МЗП:** воронка, `deal_code is not null and role_code = 'МЗП'`. Одна строка на сделку — из последнего снимка. Дата — `deal_create_dttm`, привязка по организации **и** ГОСБ.

**Окно.** `action_dt <= first_payment_dt <= конец месяца (action_dt + 2 мес.)`. Функция `last_day()` заказчика не используется: её нет в ядре, вместо неё `date_trunc` и interval. Окно действий начинается с ноября года, предшествующего январю первого года.

**Атрибуция.**
- Из действий, действующих на дату первой ЗП, побеждает самое раннее; при равной дате — МЗП > ВСП > Digital.
- Без действия — «Остальное».
- Флаги «канал действовал» дают охват и таблицу пересечений.
- Лаг — месяцев от действия до первой ЗП.

**Проверки.** Ровно один канал на НФЛ (строк `t_nflc` = строк `t_nfl`). Каналы складываются в НФЛ. Сумма сегментов и ТБ равна НФЛ. Архив и текущая витрина не делят месяц. Каждый месяц непуст.

## 3. МЗП

- **Штат:** `count(distinct saphr_id)` на последний день августа обоих лет (как у заказчика), по ТБ — отдельно.
- **Сделки по месяцам создания (янв–авг):** число; план и факт из последнего снимка; сотрудники; НФЛ, которые сделка выиграла в атрибуции.
- **Производные:** сделок на менеджера, факт на менеджера, НФЛ МЗП на менеджера, факт и НФЛ на сделку, факт / план.
- **Привязка по ГОСБ:** доля сделок, у которых есть ячейка ведомостей с той же организацией в том же ГОСБ. Если организация есть, но в другом ГОСБ — НФЛ к такой сделке не привяжутся.

## 4. Разрезы

- Сегмент, холдинг, отрасль — справочник организаций (`uzp_data_epk_consolidation`, свёрнут до организации), один срез на оба года. ТБ — из НФЛ и ячеек.
- Холдинги и отрасли: в HTML — верх по падению НФЛ и верх по росту (`BREAK_MAX`), с поиском.

## 5. Названия и правило 14

- Названия организаций и холдингов показываются, кроме содержащих ФИО (ИП, КФХ, «глава», адвокат, нотариус, отчество, инициалы). Вместо них — id орг или «название скрыто». Маска срабатывает на каждой выборке (`Workspace.sql`).
- Трёхбуквенное слово-идентификатор организации не пишется нигде — ни в коде, ни в документах (`check_no_blocked_word`).
- Латинское имя колонки в показанном SQL записано кодами символов `U&"\0069nn"`: для Postgres и Greenplum это то же имя, запрос выполняется как есть. Нужно `standard_conforming_strings = on`, это значение по умолчанию.

## 6. Ограничения

- Таблицы клика и ВСП читаются одним запросом каждая. Если на проме они не уложатся в таймаут — увеличить `SQL_TIMEOUT_MIN` или сузить период.
- Правило ГОСБ по сегменту КСБ (8591 → 8646) у НФЛ и сделок не применяется: сегмента там нет.
- План и факт сделок — данные воронки, атрибуция НФЛ — расчёт отчёта. Они не обязаны совпадать.
