# payroll_attraction — почему упало привлечение год к году

Отвечает на вопросы:
1. **Ячейки «ГОСБ × организация», август к августу.** Сколько выросло (+1 ФЛ и больше), снизилось, осталось как было. Сколько таких ситуаций роста в этом году против прошлого.
2. **НФЛ** — впервые получили ЗП в Сбере. Янв–авг этого года против прошлого, по месяцам, по каналам: МЗП, ВСП, Digital, Остальное.
3. **МЗП.** Штат вырос примерно на 50%. В какой пропорции изменились сделки, план, факт и НФЛ. На менеджера и на сделку, по ТБ.
4. **Разрезы.** Сегмент, холдинг, отрасль, ТБ. Пересечения каналов и задержка от действия до зарплаты.

На выходе один HTML в `output/`. Открывается без сети, обезличенных файлов нет.

## Определения

| | |
|---|---|
| Численность ячейки | ФЛ с `is_salary_client = 1` по `(sys_gosb_id, организация)` в августе — логика портфеля заказчика по `mis_data_payroll_m`: перекодировки ГОСБ, `relev`, справочник видов зачислений, без порога — образовательные организации и холдинг МИНОБОРОНЫ |
| Рост / снижение / без изменений | +1 и больше (вкл. новые ячейки) / −1 и больше (вкл. закрывшиеся) / 0 («10 ушли — 10 пришли») |
| НФЛ | `is_nfl and not is_overflow_fl`; до `NFL_SPLIT` — архив `bkv_bkv_uzp_data_nfl_channel`, после — `uzp_data_nfl_channel` |
| Действие | Сделка МЗП (`deal_code` есть, роль МЗП, последний снимок воронки), консультация ВСП (фильтры заказчика), консультация СБОЛ |
| Окно действия | от дня действия до конца второго месяца после него: 15 января → 31 марта |
| Канал НФЛ | самое раннее действие, действующее на дату первой ЗП; при равной дате — МЗП, ВСП, Digital. МЗП — по организации **и** ГОСБ, ВСП и Digital — по ФЛ |
| Остальное | НФЛ без действующего действия = приток − (МЗП + ВСП + Digital) |
| Штат МЗП | `count(distinct saphr_id)` с `pos_name = 'Менеджер по продаже зарплатных проектов'` на последний день периода |

Подробно, с ловушками, — [METHODOLOGY.md](METHODOLOGY.md).

## Запуск

`payroll_attraction.ipynb`, ячейки по порядку:
1. описание;
2. пакеты;
3. самопроверки без БД;
4. **параметры и запуск**;
5. главные цифры;
6. сверка с синтетикой (только открытый контур).

Витрины лежат в двух схемах: `SCHEMA` (основная) и `SCHEMA_T` (архив НФЛ, клики СБОЛ).

## Автономность

Папка ничего не импортирует из проекта: свои подключение к БД, графики, маска названий. Это проверяет `check_self_contained`. `.env` ищется в папке и выше: `ATTR_DB_URL` или `UZP_DB_URL`.

Названия организаций и холдингов показываются, кроме содержащих ФИО (ИП, КФХ и т. п.). Вместо таких — id орг цифрами или «название скрыто». В HTML нет слова-идентификатора организации — ни кириллицей, ни латиницей; в показанном SQL имя колонки записано кодами символов.

## Устройство

| Файл | Что внутри |

## Отладка снаружи

```bash
docker compose up -d                 # Postgres из корня проекта (порт 55433)
cd uzp_scripts/payroll_attraction
python3 -m attraction.synth          # схемы synth_attraction и synth_attraction_t
```

Затем тетрадка с `SCHEMA = "synth_attraction"`, `SCHEMA_T = "synth_attraction_t"`.

Ожидания синтетики считаются **независимо** — отдельной реализацией правил на pandas по тем же строкам. `check_against_synth` требует точного совпадения:
- каналов по годам;
- портфеля;
- классов ячеек;
- штата и сделок.
