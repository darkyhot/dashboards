# Оформление SQL

Действует на весь SQL в репозитории: проверенные запросы процессов (`processes/*/queries/`),
запросы методик (`methodology/queries/`), шаблоны и боевой ETL. Правила ETL-функций,
временных и целевых таблиц — отдельно в `etl/target-tables.md`.

## Регистр и отступы

- Код в нижнем регистре, включая ключевые слова. Верхний регистр не смешивать с нижним
  внутри одного файла.
- Отступ — 4 позиции; для каждого логического уровня добавляется одна табуляция, символы
  табуляции в пробелы не разворачиваются.
- Ширина кода — под окно 80 символов. Длинную строку сообщения или комментария не рвут
  посередине только ради 80 символов.
- Перенос выражения начинают на том же уровне отступа, что и в предыдущей строке.
- Каждое новое выражение — с новой строки.
- Пробелы ставятся вокруг арифметических операторов, операторов сравнения и присваивания;
  перед запятой — нет. В списке параметров и в `in (...)` значения можно перечислить в строку
  через запятую с пробелом.
- Открывающая скобка — на той же строке, закрывающая — на отдельной строке с отступом
  открывающего оператора. Содержимое скобок располагают на уровне открывающей скобки или
  правее; если сдвиг вправо получается слишком большим, содержимое сдвигают на 2–3 отступа.
  У вызова функции без параметров закрывающая скобка идёт сразу за открывающей.

## Конструкции запроса

- `select`, `from`, `where`, `group by`, `having`, `into`, `union [all]`,
  `[left|right|cross] join` — каждая на отдельной строке.
- С `select` в одну строку допустимы `distinct`, а также одно поле или переменная
  (`select cnt into v_cnt`). Во всех остальных случаях каждый элемент списка — с новой строки
  с одним отступом от ключевого слова, запятая в конце строки.
- **`select *` для выборки из таблиц, представлений и функций не используется.** Поля
  перечисляются по списку из `contract.yaml` витрины — это заодно проверяет, что поле
  задокументировано.
- Имя таблицы — с новой строки, на один отступ правее `from` / `join`. Условие соединения —
  с новой строки, на два отступа правее `join`.
- Каждое `and` / `or` — с новой строки. Если в одном фильтре три и более условия смешивают
  `and` и `or`, порядок исполнения задают явными скобками.
- `case` в одну строку только когда одна ветка `when` с одним условием и в `then` / `else`
  нет вычислений. Иначе каждая `when` и `else` — с новой строки на один отступ правее `case`,
  `end` — на отдельной строке на уровне `case`.
- `insert into <таблица>` — в одну строку.
- При более чем одной таблице у каждой таблицы алиас, и алиас проставлен у каждого атрибута.
  Алиас — первые буквы слов названия таблицы или сокращение от него. Последовательные `a`, `b`,
  `c` и `t1`, `t2`, `t3` запрещены.

## Комментарии

Комментарий обязателен к каждому запросу, вызову функции, ветвлению, циклу, CTE, сложному
фильтру и сложному вычислению. Фильтр или вычисление считается сложным, если использует:

- подзапрос;
- оконную функцию с рамкой `rows between …`, отличной от дефолтной;
- больше одного вложенного условия.

Комментарий объясняет не «что делает строка», а почему: откуда порог, почему исключаются
записи, почему берётся минимум за три периода. Если текст лога полностью повторяет комментарий
к действию, комментарий не пишут.

Файл запроса начинается с заголовка — что за процесс, какие витрины-источники и ключевые
условия отбора. Так устроены существующие `processes/*/queries/*.sql`:

```sql
-- Процесс: Задачи (tasks)
-- Проверенные запросы.
-- Задача ставится сотруднику (role_code) или руководителю, источник — src_task_as_code.
```

## Пример оформления

Пример построен на витринах оттока и их реальных полях: ключ оттока — пара `inn` + `gosb_id`,
бизнес-отсечка 3+, возврат считается по факту оттока (`processes/outflow/SKILL.md`).

```sql
/*
* Отток и возврат по ИНН и ГОСБ за отчётный месяц.
* Возврат берём из лабораторной схемы: копия в проде неактуальна.
*/
with fact_outflow as (
    select
        outflow.tb_id,
        outflow.gosb_id,
        outflow.inn,
        sum(outflow.outflow_qty) as outflow_qty
    from
        s_grnplm_ld_salesntwrk_pcap_sn_uzp.uzp_dwh_fact_outflow outflow
    where
        outflow.report_dt = '2026-10-31'
        and outflow.outflow_qty >= 3
    group by
        outflow.tb_id,
        outflow.gosb_id,
        outflow.inn
)

select
    fout.tb_id,
    fout.gosb_id,
    fout.inn,
    fout.outflow_qty,
    case
        when fout.outflow_qty between 3 and 9 then '3-9'
        else '10+'
    end as outflow_group,
    -- соединение левое: возврат может отсутствовать, отток от этого не пропадает
    coalesce(ret.return_qty, 0)::numeric / nullif(fout.outflow_qty, 0) as return_perc
from
    fact_outflow fout
left join (
        select
            ret_detail.gosb_id,
            ret_detail.inn,
            sum(ret_detail.return_qty) as return_qty
        from
            s_grnplm_ld_salesntwrk_pcap_sn_t_uzp.uzp_data_outflow_return_detail ret_detail
        where
            ret_detail.report_dt = '2026-10-31'
            and ret_detail.is_outflow_return_success
        group by
            ret_detail.gosb_id,
            ret_detail.inn
) ret
    on ret.gosb_id = fout.gosb_id
    and ret.inn = fout.inn
order by
    fout.outflow_qty desc
;
```

## Период и партиции

Условие по отчётной дате ставят всегда: месячные витрины хранят данные в `report_dt`,
и без фильтра читается вся история. Отдельно — партиционированные витрины: у них предикат
по колонке партиционирования обязателен, иначе читаются все партиции. Из текущих витрин
партиционирование объявлено у `uzp_data_payroll_m` (колонка `report_dt`); см.
`storage.partitioning` в паспорте и AGENTS.md, «Даты в витринах».

## Даты и функции-помощники

Функции-помощники работают с датами и приведением типов; вызываются с явной схемой
`s_grnplm_ld_salesntwrk_pcap_sn_t_uzp`:

```sql
select s_grnplm_ld_salesntwrk_pcap_sn_t_uzp.last_day('2022-11-29'::date);      -- 2022-11-30
select s_grnplm_ld_salesntwrk_pcap_sn_t_uzp.add_months('2022-11-29'::date, 1); -- 2022-12-29
select s_grnplm_ld_salesntwrk_pcap_sn_t_uzp.next_day('2022-11-29'::date, 'monday');
select s_grnplm_ld_salesntwrk_pcap_sn_t_uzp.trunc('2022-11-29'::date, 'mm');   -- аналог date_trunc
select s_grnplm_ld_salesntwrk_pcap_sn_t_uzp.end_of_month('2022-11-29'::date);
select s_grnplm_ld_salesntwrk_pcap_sn_t_uzp.try_cast('a23', null::bigint);     -- NULL вместо ошибки
```

Ограничения:

- `now()` возвращает `timestamp with time zone` — функции-помощники с таким типом падают,
  нужно приводить: `last_day(now()::timestamp)`.
- Поле-дату из витрины с `date_kind` в функцию не оборачивают — это ломает отсечение партиций
  и сравнения. Расчётную дату считают отдельно (`v_report_dt`, константа, подзапрос) и подставляют
  в предикат значением. Единственное оправданное исключение — данные лежат в произвольные даты
  месяца и их нужно привести к концу месяца, чтобы присоединить к месячным витринам: так сделано
  в `methodology/queries/employees.sql`.
