# Spec Delta

## Purpose

Витрина `uzp_dwh_task_trigger`: сработавшие триггеры по паре ИНН + ГОСБ за месяц или неделю,
параметры — в JSON. По ней строятся задачи сотрудникам.

## ADDED Requirements

### Requirement: Состав полей
Витрина SHALL содержать 8 полей:

| Поле | Тип | Null | Описание |
| --- | --- | --- | --- |
| `gosb_id` | int4 | нет | ГОСБ |
| `inn` | int8 | нет | ИНН |
| `modified_dttm` | timestamp | нет | Дата-время расчёта |
| `start_dt` | date | нет | Дата начала периода |
| `end_dt` | date | нет | Дата окончания периода |
| `trigger_name` | varchar(255) | нет | Заголовок триггера |
| `trigger_type` | varchar(255) | нет | Тип триггера |
| `attributes_json` | json | да | Параметры триггера |

#### Scenario: Структура
- **WHEN** витрина создана
- **THEN** поля, типы и not null — как в таблице, у полей есть описание

### Requirement: Зерно и ключ
Строка SHALL означать один сработавший триггер по паре за период. Ключ — `inn`, `gosb_id`, `trigger_name`, `start_dt`, `end_dt`.

#### Scenario: Ключ уникален
- **WHEN** расчёт завершён
- **THEN** дублей ключа нет

#### Scenario: Несколько строк источника
- **WHEN** у пары несколько ЕПК или заявлений
- **THEN** у пары одна строка на триггер

### Requirement: Период месяца
Ежемесячный расчёт SHALL брать `end_dt` из параметра и писать `start_dt` — 1-е число месяца, `end_dt` — последнее. Этот месяц — T.

#### Scenario: Октябрь
- **WHEN** `end_dt` = 2026-10-31
- **THEN** `start_dt` = 2026-10-01, `end_dt` = 2026-10-31

### Requirement: Период недели
Еженедельный расчёт SHALL брать `end_dt` из параметра и писать `end_dt` — воскресенье, `start_dt` — понедельник той же недели.

#### Scenario: Неделя
- **WHEN** `end_dt` = 2026-11-15
- **THEN** `start_dt` = 2026-11-09, `end_dt` = 2026-11-15

### Requirement: Название и тип
`trigger_name` SHALL равняться колонке «Название» интента, `trigger_type` — колонке типа («Основной» / «Вспомогательный»).

#### Scenario: Отрицательный потенциал
- **WHEN** сработал 'отрицательный потенциал'
- **THEN** `trigger_type` = 'Основной'

### Requirement: JSON
`attributes_json` SHALL содержать ключи из колонки «Параметры для JSON» интента. `month` = `end_dt` в формате 'ГГГГ-ММ-ДД'.

#### Scenario: Высокая текучка
- **WHEN** сработала 'высокая текучка' за T = 2026-09-30
- **THEN** ключи: `month` = '2026-09-30', `nfl_cnt`, `np_cnt`, `portf_last_m`, `portf_cur_m`

### Requirement: Время расчёта
`modified_dttm` SHALL быть одним на все строки запуска и равняться времени запуска.

#### Scenario: Один запуск
- **WHEN** запуск записал несколько строк
- **THEN** `count(distinct modified_dttm)` = 1

### Requirement: Пара без ИНН или ГОСБ
Строка SHALL писаться, только если у пары есть ИНН и ГОСБ.

#### Scenario: ГОСБ нет в справочнике
- **WHEN** ГОСБ заявления не найден в справочнике
- **THEN** строки по заявлению нет

### Requirement: Перерасчёт
Повторный запуск за период SHALL заменять строки триггеров своей функции за этот период. Строки другой функции и других периодов не меняются.

#### Scenario: Два запуска
- **WHEN** месяц T посчитан дважды
- **THEN** строк за T столько же, дублей нет

#### Scenario: Неделя не трогает месяц
- **WHEN** посчитана неделя внутри T
- **THEN** строки ежемесячных триггеров за T не изменились

### Requirement: Нет данных источника
Если у источника нет данных за период, расчёт SHALL поставить статус 98, записать в лог источник и даты и не менять витрину.

#### Scenario: Нет T в holding_metric
- **WHEN** в `uzp_dwh_company_holding_metric` нет `report_dt` = T
- **THEN** статус 98, витрина не изменилась

### Requirement: Проверка ККД
Если ключ в подготовленных данных не уникален, расчёт SHALL поставить статус 97 и не менять витрину.

#### Scenario: Дубль ключа
- **WHEN** в подготовленных данных дубль ключа
- **THEN** статус 97, витрина не изменилась

### Requirement: Сверка с источником
Число строк триггера за период SHALL равняться числу пар источника, у которых выполнено условие триггера.

#### Scenario: Отрицательный потенциал
- **WHEN** месяц T посчитан
- **THEN** строк 'отрицательный потенциал' столько же, сколько пар за T с `np_cnt > emp_potential_qty`
