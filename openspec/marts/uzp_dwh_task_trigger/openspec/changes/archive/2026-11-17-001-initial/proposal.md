# Proposal

## Why

Задачи сотрудникам строятся по триггерам клиента. Витрины триггеров нет. Новая витрина
`uzp_dwh_task_trigger` хранит сработавшие триггеры по паре ИНН + ГОСБ с параметрами в JSON.

## What Changes

- Витрина `uzp_dwh_task_trigger`: одна строка — один сработавший триггер по паре ИНН + ГОСБ за период.
- Функция `uzp_dwh_task_trigger_month_calc` рассчитывает 15 триггеров за календарный месяц даты `p_end_dttm`:
  - ЕПП флаг, Ср чек ниже среднего, Отрицательный потенциал, Кп первое зачисление;
  - Сезонный тип деятельности, Высокая текучка, Есть договор нет зачисления;
  - Контактная политика 4 месяца, Доля по клиенту больше 90%;
  - 4 триггера по заявлениям ВСП / МП СБОЛ: бумажные и электронные, за месяц и за 3 месяца;
  - 2 триггера оттока.
- Функция `uzp_dwh_task_trigger_week_calc` рассчитывает 2 триггера по заявлениям ВСП / МП СБОЛ за неделю Пн–Вс, в которую попадает `p_end_dttm`.

Вне рамок — триггеры с пометкой «ограничение» в интенте.

## Capabilities

### New Capabilities
- [Витрина (`trigger-mart`)](specs/trigger-mart/spec.md) — поля, ключ, периоды, перерасчёт, обязательные проверки ККД (статус 98).
- [Месячный расчёт (`monthly-triggers`)](specs/monthly-triggers/spec.md) — правила и JSON 15 ежемесячных триггеров.
- [Недельный расчёт (`weekly-triggers`)](specs/weekly-triggers/spec.md) — правила и JSON 2 еженедельных триггеров.
